# 로드맵

**목표:** 내 방을 본뜬 시뮬레이션 안에서, 자연어(키보드, 이후 음성)로 명령하면 환경을 인식하고 행동하는 **나만의 애완 오리** 만들기.
명령이 없을 때도 스스로 돌아다니고, 다가오고, 심심해하는 반응형 애완동물이 목표입니다.

## 설계 원칙

1. **LLM은 "무엇을 할지"만 정하고, "어떻게 움직일지"는 RL 정책이 맡습니다.**
   LLM은 수 초에 한 번 생각하지만, 관절은 초당 50번 제어해야 하기 때문입니다.
2. **추론할 때 시뮬레이터의 정답 좌표를 쓰지 않습니다.** 카메라와 IMU 정보만 씁니다.
   나중에 실물 로봇(sim2real)으로 옮기기 위해서입니다.
   정답 정보는 **학습 데이터를 만들 때만** 씁니다.
3. **ROS2로 모든 부품을 연결합니다.** 실물로 옮길 때는 "MuJoCo 브리지 노드"를 "실물 로봇 노드"로 바꾸기만 하면 되게 만듭니다.

## 전체 구조

```
 키보드 / 마이크 ──▶ [STT: faster-whisper] ──▶ "go push the red ball"
                                                   │
                                                   ▼
                       [두뇌: 로컬 LLM (Ollama, 8B급 도구 호출 모델)]
                        도구 목록 + 지금 보이는 물체 목록을 보고 순서를 정함
                        → walk_to("red ball") → push("red ball")
                                                   │  ROS2 Action
         ┌─────────────────────────────────────────┼──────────────────────────┐
         ▼                                         ▼                          ▼
 [행동 관리: Behavior Tree]             [기술(Skill) Action 서버]      [인식]
  명령이 없을 때 돌아다니기,             walk_to / follow / look_at     머리 카메라 RGB-D
  다가오기, 심심해하기                   sit / dance / push_ball        → YOLO 물체 탐지
  (내부 상태: 심심함, 에너지)            happy / sad + 효과음           → 물체 3D 위치
                                                   │                    → 의미 지도
                                                   ▼
                       [RL 정책 (ONNX)] 속도 + 고개 명령 → 관절 14개 (50Hz)
                                                   │
                                                   ▼
                       [MuJoCo 시뮬레이션 + 뷰어] ⇄ ROS2 브리지 노드
```

> 걷기 정책의 관측에는 고개 명령 칸이 있지만, **고개 명령을 따르도록 학습되지는 않았습니다**(측정: 관측에만 넣으면 고개가 안 움직임).
> 그래서 고개 4관절은 정책 출력 대신 명령값으로 직접 덮어씁니다(걷기에는 영향 없음). 덕분에 `look_at`, 감정 표현은 새로 학습하지 않고 만들었습니다.

**한 일 (진행 순서):** 준비(걷기 정책) → 0 Ubuntu 환경 → 1 방 + ROS2 브리지 → 2 기본 기술 → 3 인식 → 4 언어→행동 → 5 자율 행동 → 6 새 RL 기술(일부: 공 밀기는 ROS 연동 실패, 앉기·버튼은 모델 변경 필요) → 8 개방형 탐지 → 탐험

**다음 순서:**
1. 탐험 마무리: 자율 행동·실제 LLM 명령과 함께 종단 시험 → frontier 탐험(지나온 곳을 격자 지도로 기억)
2. 공 밀기 재시도: 센서/구조 변경(아래를 보는 카메라, 더 나은 이동량 추정, 폐루프 시각 서보)
3. 몸통/머리 충돌 모델 추가 → 앉기·버튼 → 계단
4. 7단계 음성 입력
5. 남은 작은 일: 쉬기 행동 실제 발동 확인, 효과음, 실제 방 치수 측정

단계별 측정 결과와 한계는 [PROGRESS.md](PROGRESS.md).

### ✅ 8단계 (추가 결정, 2026-11-09): 개방형 탐지 — VLM 으로 처음 보는 물체 찾기
- **배경:** 현재 구조는 VLA 가 아니라 `LLM(글만 이해) → 도구 호출 → 기술` 파이프라인이고, 인식은 YOLO 가 아는 4종류(red_block, green_block, blue_ball, person)만 가능. LLM 은 이미지를 보지 않음
- **계획 (6단계 새 RL 기술을 끝낸 뒤):** 인식 단계에 비전-언어 모델(VLM)을 추가해 "이 이미지에서 노란 컵이 어디 있나?" 같은 질문으로 **학습하지 않은 물체도 탐지**. 나머지 구조(도구 호출, 시각 서보잉, 지도)는 그대로 유지
- [x] VLM 후보 조사/선정 — OWLv2 선택(측정표는 docs/PROGRESS.md) (RTX 3080 10GB 에서 LLM 과 함께 돌 수 있어야 함: GPU 메모리 계획 표 갱신)
- [x] 개방형 탐지 노드: 이미지 + 글 질문 → 상자/점 → 기존 깊이 파이프라인으로 3D 위치
- [x] 방에 새 물체(예: 노란 컵) 추가 후 "go to the yellow cup" 성공률 측정, YOLO 와 속도/정확도 비교
- **결과물:** 학습하지 않은 물체 이름으로 명령해도 찾아가는 데모

## GPU 메모리 계획 (RTX 3080 10GB)

| 실행 중일 때 | 사용량(대략) |
|---|---|
| LLM 8B (4비트) | 5~6 GB |
| YOLO | 약 1 GB |
| faster-whisper small | 약 1 GB |
| MuJoCo + 걷기 정책(ONNX) | CPU에서 실행 |

> **RL 학습(MJX)은 GPU를 거의 다 쓰므로** 학습할 때는 다른 것들을 끄고 따로 돌립니다.
